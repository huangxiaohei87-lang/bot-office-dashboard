# 动效说明

本期只出设计稿，**不做成可交互产品**，不写产品代码，不加新动画库，不要音效或 BGM。进入工程后，若采用画布库，只浅用平移/缩放/放置房间（已批准可浅用 LeaferJS MIT 核心，不引入其商业插件，不做成编辑器）。

## 1. 画布

- 默认镜头固定为西南 2:1 等轴测，不可旋转。
- 允许平移、缩放。缩放时人物、灯牌和侧面姓名牌保持可辨读，不出现非整数错位的像素风。
- 本设计稿用静帧 + 极弱工具条表示「可平移缩放，不可旋转」，不提供可拖拽原型。装进整体窗口后，这条说明放在左侧近黑圆角模型容器下方的纸白壳上，服从左右分栏，不要做成深色控制台控件，也不要没入黑底，不要做成另一套强竞争的控件。

## 2. 开灯 / 关灯切换

状态变化是房间级的，不是贴一张开关图块。开灯与关灯的过渡以**室内明暗和色温**为主（约 200–400ms，不闪烁），不要再用灯牌发光或溢光作为默认过渡。界面层以 2026-11-16 01:01 为准：办公室名牌是不发光的建筑名牌。

- 开灯 → 关灯：室内明度下降、色温转冷灰蓝、落地灯/吊灯灯罩停止发光、窗光与地面光池收掉。门楣/侧招名牌仍在，牌面可略转冷灰，但两侧都不做发光或溢光；字仍可认出。家具保留，人物按规则离开或不再绘制。
- 关灯/空地 → 开灯（将来创建新分组时）：先出现地基，再长出墙与家具，最后室内亮起来（窗光、落地灯、吊灯可恢复）。名牌随建筑出现，但是干净哑光牌面，不要先闪出一块发光灯箱。未创建空地没有房间名牌。过渡以 200–400ms 的明度与色温交叉为宜，不必做复杂粒子。
- 用 CSS 即可表达（亮度、饱和度的交叉）。不要给名牌加一层持续溢光。本期不要求新动画库。

界面层的氛围（写入 `界面设计稿/`，不改已确认的场景静帧）也必须克制、短、不要闪烁。产品外壳仍是纸白；模型视口内部是近黑圆角容器：

- **一点点环境光（静态、柔和）：** 开灯房间向邻近黑色地面晕出的暖色环境光是静态、克制的邻地晕染，过渡须柔和、有远近，不要做成沿建筑描边的均匀光圈，也不要呼吸闪烁或随时间跳动的光晕。不要舞台追光或整幅暖雾。名牌不参与发光，也不要给名牌加一层持续溢光。
- **空地：** 未创建空地在近黑地面上保持深石板色，可读「未创建」，不要压到字形消失，也不要抬成浅地基。不要做呼吸闪烁。
- **名牌不发光：** 不要把「灯牌点亮 / 溢光」当作默认过渡。开灯时名牌保持干净可读的哑光牌面；关灯时只随室内转冷暗，仍不发光。未创建空地始终没有房间名牌，不要先闪出一块空灯箱再熄灭。

## 3. 姿态与状态如何切换

每个岗位是同一套形象的姿态切换，而不是换一套角色。岗位姓名牌始终跟在人物侧面，不挡头；人离开后，姓名牌随人走，原工位不再留岗位牌。

| 状态 | 视觉 | 建议过渡（工程阶段） |
| --- | --- | --- |
| 在岗工作 | 坐在桌子北侧，面朝南（朝向镜头），椅背在人身后，显示器在桌南沿、屏幕朝人；手臂伸向南侧桌面；姓名牌在身侧 | 从空闲走到桌北坐下，面向屏幕，双臂落到南侧桌面，约 300ms |
| 空闲 | 在本房内站立或轻坐，未埋头；姓名牌仍在身侧 | 从北侧工作椅上起身，或原地放松 |
| 离开 | 工位空着，空椅留在与在岗相同的桌北位置（椅背在北、座位朝南）；椅旁出现弱「离开」标记（不与邻座姓名牌或灯牌叠字）；人物走到门口或房外，姓名牌随人 | 先从北侧工作椅起身，再沿路径走到门外；工位只留同一张朝向的空椅与「离开」标记，不要把离开重做成在岗坐姿 |
| 待汇报 | 持文件，面向老大办公室门口或进入室内；姓名牌在身侧 | 走到门前后改为持件站立 |
| 茶水间闲逛 / 休息 | 端杯走动，或坐进沙发座位（臀在坐垫上、背靠椅背，不坐扶手/靠背/围挡）；姓名牌在身侧 | 空闲岗位可从本房走到茶水间并坐进座位；不必再造「未分组」角色 |

在岗与离开使用同一侧、同一朝向的椅位：都在桌子北侧，椅背在北、座位朝南。离开时把人从这张椅子上带走，椅子留在原处，不要再把空椅放到桌子南侧，也不要把离开的人画回在岗坐姿。

走位用短路径（直线或一两个折点），不要做成可自由寻路的游戏 AI。同一「当前状态」画布上一人只出现在一处：离开工位后，原工位只保留空椅和「离开」标记，不再把同一人画在两个房间。姿态可以是 2–4 帧的替换，或仅用关键姿势交叉淡入，不必上骨骼系统。

## 4. 交互预留（只写预留，不实现）

对应场景稿中的三帧注释分镜，以及整体界面里对「点击助理」的修订。姓名牌位置与灯牌不改变这三项预留的含义，只要求注释、淡框和路径不要挡住灯牌字面或人物头部。右侧对话为常驻；其余两项（派活走来、完工汇报）仍只预留，不实现。

### 4.1 点击场景里的助理，只聚焦右侧常驻对话

- 右侧与「助理」的对话区是**常驻界面**，默认就在完整窗口的右边，不是点开才出现的临时浮层，也不是另开一页。栏体是内缩的圆角卡片（半径 16px，四边空隙 18px）；聚焦或开合时不要把栏体切成方角，也不另弹独立聊天窗。
- 预留点位：场景里的助理本人（或助理工位热区）。
- 点击助理后，应落到右侧同一对话栏：聚焦或接上正在进行的聊天（例如顶栏与输入框给予轻度强调、输入焦点进入该栏）。**不要再弹一个打乱左右布局的独立聊天窗。**
- 设计稿用淡框、虚线和一句注释标出：「预留：点击场景里的助理，右侧对话聚焦 / 不另外弹出聊天窗」。`界面设计稿/04-点击助理聚焦对话-预留.png` 即此预留，不是可点击原型。
- 场景稿里原有的 `06-交互预留-1-点击对话.png` 仍是较早的点位示意，含义与本条一致，并已由整体界面修订为「聚焦右侧常驻对话」。不要再按「另开对话层盖在场景上」或「弹出独立聊天窗」去实现。
- 本期不做成可点击产品。工程阶段若实现，也必须保持左右同屏，不得用中后台表格替换轴测场景。

### 4.2 助理派活后，对方从自己工位走过来

- 预留：被派岗的人物切换为走动姿态，沿虚线从自己工位走到老大办公室附近；姓名牌随人移动。
- 原工位切换为「离开」（空椅 + 弱标记，无岗位桌牌）。
- 设计稿用走动姿态 + 路径虚线示意，如「工程」离开 APP制作台走向老大办公室。
- 本期不实现自动走位。

### 4.3 做完后来汇报

- 预留：该人物在老大办公室门前或室内，切换为「待汇报」姿态（持文件，面向助理）。
- 设计稿只示意姿态与站位，不画已完成的汇报表单或审批界面。站位不要紧贴到把门楣灯牌字面挡住。
- 本期不实现走位或对话。

## 5. 明确不做

- 不加新动画库；不引入需要付费或专用许可的动效框架。
- 不要音效、不要 BGM。
- 不要可轨道旋转的相机动画。
- 不要 8-bit 闪烁、CRT 或像素抖动。
